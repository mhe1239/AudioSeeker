# 기술 사양

## 플랫폼과 스택

- Android 앱 모듈은 Kotlin, Jetpack Compose, Material 3을 사용한다.
- 최소 SDK는 30, 대상·컴파일 SDK는 35이며 Java 17을 사용한다.
- 로컬 음악 재생은 AndroidX Media3와 `MediaSessionService` 기반으로 구성한다.
- 오디오 라이브러리는 `MediaStore`에서 읽는다. 파일 삭제·권한·백그라운드 실행은 Android 버전별 정책을 먼저 확인한다.

## 상태와 재생

- 재생 큐, 현재 곡, 재생·반복·셔플 상태, 탐색 위치는 `PlayerViewModel`과 Media3가 단일 출처가 된다.
- Compose는 상태를 표시하고 사용자 의도를 전달한다. Composable에 별도 장기 재생 상태나 플레이어 인스턴스를 만들지 않는다.
- 백그라운드 재생, 잠금 화면 제어, 알림 재생바는 `PlaybackService`와 미디어 세션의 책임이다.
- 재생 속도는 설정에서 0.5배부터 2.0배까지 0.1배 단위로 선택하며, 플레이어에 즉시 반영하고 다음 실행에도 복원한다.
- 파일 경계 무음 줄이기는 기본값을 끄고, 켠 경우에만 각 로컬 파일의 처음 3초와 마지막 5초를 별도로 디코딩해 파일 시작·끝의 연속 무음만 최대 1.5초 클리핑한다. Media3의 전체 무음 건너뛰기는 파일 내부의 강의 침묵까지 바꿀 수 있으므로 사용하지 않는다. 분석·디코딩에 실패하면 해당 파일은 원본 구간 그대로 재생한다.
- 셔플과 반복은 현재 폴더·검색 결과 등 현재 재생 큐 범위에서 동작한다.
- 자동 끄기 타이머의 만료 시각과 현재 곡 종료 대상은 `SharedPreferences`에 저장하고, 실제 만료 처리·복원·일시정지는 `PlaybackService`가 담당한다. 기본값은 끄기다.

## UI와 접근성

- 모든 색상은 `AudioSeekerTheme`의 의미 기반 토큰으로 표현한다. 화면마다 원시 색상값을 추가하지 않는다.
- 밝은 테마, 청록 다크 테마, 표준 다크 테마를 지원하며 시스템 설정과 앱 설정이 일관되게 반영되어야 한다.
- 잠금 중에는 곡 변경·탐색을 막고 재생/일시정지는 허용한다. 잠금 해제 제스처, 접근성, 작은 창 높이에서도 탐색 바가 사라지지 않아야 한다.
- 문자열은 리소스로 관리하고, 아이콘·단축키 정의는 적절한 `res/` 하위 폴더에 둔다.

## Android 통합

- 루틴용 진입점은 Android 앱 바로가기의 재생 동작으로 제공한다. 제조사 루틴 앱이 이 바로가기를 노출하는지는 기기·OS 통합 정책에 따라 달라질 수 있다.
- 알림창의 재생 컨트롤은 서비스가 활성 미디어 세션과 재생 가능한 메타데이터를 제공할 때 시스템이 표시한다. 화면 UI만으로 대체하지 않는다.

## REA 사용 규칙

- APK·네이티브 라이브러리·실행 중 프로세스처럼 런타임 증거가 필요한 분석에서는 REA의 활성 스킬과 MCP 도구 지침을 우선한다.
- REA 결과에는 관찰한 사실, 그로부터의 추론, 아직 확인하지 못한 사항을 나누고 증거 식별자를 남긴다.
- 단순 소스 구현, 문서 작성, 일반 코드 검토에 REA 실행을 요구하지 않는다.
