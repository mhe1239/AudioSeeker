# 작업 보고서: 서비스 종료 뒤 마지막 곡 표시 복원

- 작성일: 2026-10-30
- 상태: 구현 완료 · 실제 기기 검증 대기
- 관련 요구사항: `REQUIREMENTS.md`의 파일별 이어 듣기

## 원인

- `PlaybackService`가 장시간 비활성 뒤 종료돼 빈 Media3 세션으로 다시 연결되면, 기존 구현은 저장된 마지막 곡 ID와 위치를 새 세션에 넣지 않았다.
- 그 결과 `syncPlayerState()`가 빈 서비스의 상태로 UI를 갱신하면서 현재 재생 영역이 사라지고 사용자가 곡을 다시 골라야 했다.

## 변경 내용

- `PlayerViewModel`은 MediaStore 로드와 미디어 컨트롤러 연결이 모두 끝난 뒤 서비스에 현재 항목이 없으면 마지막 곡을 저장 위치로 준비한다.
- 복원 과정은 `prepare()`까지만 호출하며 자동 재생하지 않는다. 재생 버튼과 다음/이전 곡은 복원한 큐를 그대로 사용한다.

## 근거와 후속 검증

- Media3 공식 문서는 일시정지·정지·실패 상태가 10분 넘게 이어지면 `MediaSessionService`가 포그라운드 서비스 상태에서 내려가 시스템이 종료할 수 있다고 설명한다. 따라서 서비스가 없는 장시간 비활성 뒤 복원 경로가 필요하다.
- `./gradlew.bat assembleDebug`로 Kotlin 컴파일과 디버그 APK 생성을 확인했다. 기존 Media3 클립 API의 사용 중단 경고 2건 외에 오류는 없었다.
- 현재 ADB 기기가 연결되지 않아 Galaxy S23+에서 서비스 종료를 재현해 마지막 항목·저장 위치가 일시정지 상태로 복원되고 재생 버튼에서 이어지는 검증은 남겨 둔다.
