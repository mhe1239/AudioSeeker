# 작업 보고서: 재생 중 바로가기 재진입 유지

- 작성일: 2026-10-30
- 상태: 완료
- 관련 요구사항: `REQUIREMENTS.md`의 앱 바로가기 재생 동작

## 원인

- Galaxy S23+에서 홈으로 나갔다가 런처로 AudioSeeker를 다시 열면, 기존 작업과 프로세스는 유지됐다.
- 그 직후 시스템 UI가 `PLAY_LAST_TRACK` 바로가기 인텐트를 호출했고, 기존 구현은 이미 재생 중이어도 마지막 곡을 다시 큐에 넣고 저장 위치에서 재생을 시작했다.
- 이 흐름이 `MainActivity`를 새로 만들면서 스플래시 화면이 다시 표시되고, 재생이 약 1초 끊긴 것처럼 보이는 원인이었다.

## 변경 내용

- `MainActivity`를 `singleTop`으로 선언해 최상위 화면에 바로가기 인텐트가 오면 새 활동 대신 `onNewIntent()`로 전달한다.
- `PlayerViewModel`은 미디어 컨트롤러가 이미 재생 중이면 마지막 곡 재생 바로가기 요청을 무시한다.

## 검증

- `./gradlew.bat assembleDebug` 성공. 기존 Media3 클립 API의 사용 중단 경고 2건 외에는 오류가 없었다.
- Galaxy S23+ (`SM-S916N`, Android 16)에 기존 데이터 유지 방식으로 APK를 설치했다.
- 재생 바로가기에서 시작한 뒤, 홈 화면으로 이동하고 런처 재진입 후 같은 바로가기 인텐트를 다시 호출했다. 두 호출은 모두 `LAUNCH_SINGLE_TOP`으로 처리됐고 프로세스 PID는 `27467`로 유지됐다.
- 미디어 세션은 재진입 전 `PLAYING`, `978.874초`(1.1배)에서 재진입 뒤 `PLAYING`, `985.575초`로 연속 진행했다. 재생을 다시 시작하거나 저장 위치로 되돌아간 흔적은 없었다.
